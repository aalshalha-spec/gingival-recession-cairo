# Cairo Classification of Gingival Recession

**Project:** *A Hybrid CNN–Transformer with Bidirectional Cross-Attention for Cairo Classification of Gingival Recession and Rule-Based Treatment Suggestion from Intraoral Photographs*

This repository contains the Jupyter notebook used to train and evaluate the image-classification experiments and to generate the study's evaluation outputs. The notebook writes its supporting Python modules during execution, runs the experiments in three parts, and creates prediction archives, analysis tables, and figures.

The experimental setup described in the manuscript uses Kaggle with an NVIDIA T4 GPU (16 GB memory) and Internet access for pretrained weights. Other environments may work, but runtime and numerical results can differ.

> **Scope:** The classifier predicts one of four image labels—healthy gingiva, RT1, RT2, or RT3—and maps the predicted label to a predefined management pathway. It is a research and decision-support aid, not a stand-alone diagnostic system or a personalised treatment plan.

| `4` | Gingival margin |

## Model architecture

### Proposed hybrid

The proposed model is the DINOv2-small + EfficientNetB0 hybrid (`h_effb0`):

- **Global branch:** DINOv2-small processes the full photograph. Its class token is concatenated with the mean of its patch tokens and passed to the classification head.
- **Local branch:** a frozen ImageNet-pretrained EfficientNetB0 processes the zoomed gingival view and supplies 49 spatial tokens from its final 7 × 7 feature map.
- **Fusion:** the two token streams are projected to 256 dimensions and exchange information through bidirectional cross-attention with four heads. Each direction includes residual connections, layer normalisation, and a feed-forward block.
- **Logit correction:** attention-pooled fused features produce a correction added to the DINOv2 classification logits. The correction layer is zero-initialised and regularised during training.
- **Anatomical supervision:** a mask head predicts the six tissue layers on DINOv2 patch tokens. Its weighted auxiliary loss is used during training only.

At inference, only the photograph is needed; annotation masks are not used.

### Comparison models

The experiments include four hybrid CNN–Transformer branches:

- DINOv2-small + ConvNeXt-XXLarge with CLIP-pretrained weights (`h_xxl`).
- DINOv2-small + MobileNetV2 (`h_mnv2`).
- DINOv2-small + EfficientNetB0 (`h_effb0`, proposed model).
- DINOv2-small + MaxViT-T (`h_maxvit`).

Single-branch comparisons include DINOv2-small, DINOv2-base, DINOv2-large, ConvNeXt-XXLarge, MobileNetV2, EfficientNetB0, and MaxViT-T.

## Experimental protocol

The full notebook protocol uses five case-grouped development folds and three named seed tracks. For each outer fold, 10% of each class in the remaining training data is assigned to an inner split for early stopping, keeping similarity groups together. Each model arm can therefore have up to 15 fold runs (five folds × three seed tracks).

### Image preprocessing and augmentation

- **Full view:** preserve the photograph's aspect ratio, scale its longer side to 224 pixels, and pad to 224 × 224.
- **Zoom view:** use the central gingival region (68% for deterministic evaluation). During training, a random square crop retaining 60–76% of the resized image side is used.
- **ConvNeXt-XXLarge:** its zoom input is converted to CLIP normalisation and resized to 256 × 256; the other image inputs use 224 × 224 and ImageNet normalisation.
- **Full-view training augmentation:** random scale of 85–100% and repositioning, JPEG compression (quality 60–95, probability 0.5), Gaussian blur (sigma 0.3–0.8, probability 0.3), horizontal flip, rotation up to 10°, and brightness/contrast changes up to 20%.
- **Zoom-view training augmentation:** random square crop followed by horizontal flip, rotation up to 10°, and brightness/contrast changes up to 20%.
- **Colour:** hue and saturation are not altered because gingival colour is clinically informative.
- **Masks:** undergo the corresponding geometric transformations using nearest-neighbour interpolation.

### Training schedule

| Component | Setting |
|---|---|
| Optimiser | AdamW |
| Batch size | 32 |
| Weight decay | 0.05 |
| Stage 1 | Backbones frozen; train heads, fusion layers, and mask head; learning rate 1e-3; up to 15 epochs |
| Stage 2 | Unfreeze the last four DINOv2 blocks; backbone learning rate 5e-5 with layer-wise decay 0.75; head learning rate 1e-4; up to 15 epochs |
| Early stopping | Inner-split loss; patience 5 epochs |
| Class weighting | Inverse class frequency in the training fold |
| Classification-head dropout | 0.3 |
| Fusion | 256 dimensions; four attention heads; 512-unit feed-forward block; dropout 0.1 |
| Correction penalty | 0.3 × mean(Δz²) / mean(z²) |
| Anatomical loss | Binary cross-entropy over six tissue layers; weight 0.5 |

The CNN branches remain frozen. The DINOv2 branch is fine-tuned in Stage 2 as described above.

If a Kaggle session reaches its time limit, rerun the same part with the original dataset and its required earlier archives attached. Completed runs are skipped; unfinished runs can continue. ## Evaluation

The notebook calculates accuracy, balanced accuracy, macro-F1, quadratic weighted kappa, macro-AUC, log loss, per-class precision/PPV, sensitivity/recall, specificity, F1, expected calibration error, and confusion matrices. It also records non-adjacent-class errors and treatment-pathway agreement.

The analysis code performs paired mid-p McNemar comparisons for classification outcomes and paired permutation testing for log loss. Confidence intervals are obtained by bootstrap resampling; subgroup proportions are reported with Wilson intervals in the manuscript. Cross-validation variability is summarised across the 15 fold runs.

### Robustness evaluation

The test images are evaluated after six image-quality degradations:

| Condition | Transformation |
|---|---|
| `jpeg_q30` | JPEG compression, quality 30 |
| `jpeg_q10` | JPEG compression, quality 10 |
| `downscale_0.5` | Downscale to 50%, then resize to the original dimensions |
| `downscale_0.25` | Downscale to 25%, then resize to the original dimensions |
| `blur_s1.5` | Gaussian blur, sigma 1.5 pixels |
| `blur_s3` | Gaussian blur, sigma 3.0 pixels |

### Grad-CAM

Grad-CAM is computed from the final DINOv2 Transformer block for the predicted class. The analysis compares activation within the clinical region (teeth, attached gingiva, gingival margin, papilla, exposed root) and the recession region (gingival margin, papilla, exposed root). The notebook saves per-run `gradcam.npz` files for the designated Grad-CAM arms and creates `Fig4_gradcam.png` when examples are available.

## Treatment pathway mapping and clinical limitations

The generated `treatment_mapping.py` module provides a deterministic lookup from the predicted class to a predefined pathway:

| Predicted class | General pathway in the manuscript |
|---|---|
| `HEALTHY` | Preventive monitoring and routine maintenance |
| `RT1` | Aim for complete root coverage; CAF with or without CTG, or tunnel/VISTA approaches as appropriate |
| `RT2` | Aim for maximum achievable root coverage; CTG-based procedures may be considered |
| `RT3` | Individualised management, including tissue stabilisation, soft-tissue augmentation, plaque control, and aesthetic considerations |

These are class-level pathways, not personalised prescriptions or a clinical guideline. The manuscript notes that probing measurements were unavailable, RT3 was the smallest test class (20 images), comparisons selected after cross-validation are exploratory, and the pathways have not been prospectively evaluated in clinical practice. Periodontal probing and clinical assessment remain necessary, especially when distinguishing RT2 from RT3.

## Paper-to-code consistency notes

The central model design, active dataset size, five-fold case grouping, two-stage training schedule, frozen CNN branches, training-only anatomical supervision, degradation evaluation, and Grad-CAM procedure are represented in the notebook. Three details should be reconciled before describing the notebook and manuscript as a fully identical, end-to-end reproduction:

1. **MobileNetV2 late-fusion ablation:** Section 3.5 of the manuscript says that the same ablation variants were trained for the ConvNeXt-XXLarge and MobileNetV2 hybrids. The current notebook includes `h_xxl_late`, `h_xxl_nomask`, and `h_mnv2_nomask`, but does not define or run `h_mnv2_late`. Add that experiment to Part B and the analysis, or narrow the manuscript wording to match the implemented experiments.
2. **Model-selection automation:** the manuscript describes selecting the proposed hybrid from the four hybrids using six cross-validation criteria. The notebook's analysis defaults to `GR_PROPOSED="h_effb0"`; it reports the comparisons but does not implement the complete six-criterion selection-and-tie-break procedure as an automatic selection step. The code therefore treats `h_effb0` as the already selected model. Add the selection procedure to the code or state clearly that selection was performed before the analysis notebook was run.
3. **Seed definition:** the notebook defines three seed offsets (101, 202, 303), then adds the outer-fold index when setting the per-run random seed. The resulting per-fold seed values are 101–105, 202–206, and 303–307. Confirm that this is the intended meaning of the manuscript's “three random seeds”; otherwise adjust the code or make the fold-specific seed scheme explicit in the methods.

The manuscript also states that a requirements file accompanies the public code, while the supplied notebook package currently has no pinned `requirements.txt`. Add the actual file or update the data-and-code availability statement accordingly.
